# 2. User Stories

> Παραδοτέο, σημείο 3.

Κάθε ιστορία ακολουθεί τη μορφή **«Ως ⟨ρόλος⟩, θέλω ⟨λειτουργία⟩, ώστε
⟨όφελος⟩»**, με κριτήρια αποδοχής σε μορφή Given/When/Then.

Τα κριτήρια αποδοχής **δεν είναι διακοσμητικά**: όσα φέρουν αναφορά σε test
έχουν ήδη μεταφραστεί σε εκτελέσιμο έλεγχο που τρέχει στο pipeline. Αυτή η
ιχνηλασιμότητα — από την ιστορία χρήστη μέχρι το πράσινο check — είναι το
ζητούμενο της απαίτησης 8.

Προτεραιότητα κατά MoSCoW: **M** must, **S** should, **C** could.

---

## Επικός στόχος Α — Υποβολή αναφοράς

### US-01 · Υποβολή καθυστέρησης `M`

**Ως** επιβάτης που περιμένει στη στάση,
**θέλω** να δηλώσω σε λίγα δευτερόλεπτα ότι η γραμμή αργεί και πόσο,
**ώστε** η αναμονή μου να παράγει χρήσιμη πληροφορία για τους επόμενους.

- **Given** είμαι συνδεδεμένος και έχω επιλέξει γραμμή
  **When** υποβάλλω αναφορά με εκτιμώμενη καθυστέρηση σε λεπτά
  **Then** η αναφορά καταγράφεται με χρονοσήμανση και συμπεριλαμβάνεται στην
  επόμενη εκτίμηση της γραμμής.
- **Given** η εκτιμώμενη καθυστέρηση είναι εκτός λογικού εύρους (< 0 ή > 180΄)
  **When** υποβάλλω
  **Then** η αίτηση απορρίπτεται με σαφές μήνυμα, όχι με γενικό σφάλμα.

### US-02 · Προστασία από κατάχρηση `M`

**Ως** υπεύθυνος λειτουργίας,
**θέλω** ένας χρήστης να μην μπορεί να υποβάλλει επανειλημμένα για την ίδια γραμμή,
**ώστε** ένας μόνο άνθρωπος να μην αλλοιώνει την εικόνα.

- **Given** έχω ήδη υποβάλει αναφορά για τη γραμμή πριν από 3 λεπτά
  **When** προσπαθώ ξανά
  **Then** λαμβάνω `429` με πεδίο `retry_after`.
  → `test_ratelimit.py::TestCooldown::test_second_submission_within_window_blocked`
- **Given** η προηγούμενη υποβολή μου έγινε πριν ακριβώς 10 λεπτά
  **When** υποβάλλω ξανά
  **Then** η υποβολή γίνεται δεκτή.
  → `test_ratelimit.py::TestCooldown::test_submission_exactly_at_window_edge_is_allowed`

### US-03 · Επιβεβαίωση ή διάψευση `S`

**Ως** επιβάτης που βλέπει υπάρχουσα αναφορά,
**θέλω** να δηλώσω αν συμφωνεί με την εμπειρία μου,
**ώστε** να ενισχύεται ή να αποδυναμώνεται χωρίς να χρειάζεται νέα αναφορά.

- **Given** υπάρχει ενεργή αναφορά για τη γραμμή
  **When** την επιβεβαιώνω
  **Then** ο βαθμός αξιοπιστίας του συντάκτη αυξάνεται.
  → `test_reliability.py::TestComputeReliability::test_confirmations_increase_weight`
- **Given** ένας χρήστης έχει διαψευστεί επανειλημμένα
  **When** υπολογίζεται ο βαθμός του
  **Then** σημαίνεται ως ύποπτος για κακόβουλη χρήση.
  → `test_reliability.py::TestSpammerDetection::test_flags_consistently_disputed_user`

## Επικός στόχος Β — Ενημέρωση πριν τη μετακίνηση

### US-04 · Κατάσταση γραμμής με μια ματιά `M`

**Ως** επιβάτης πριν βγω από το σπίτι,
**θέλω** να δω αν η γραμμή μου λειτουργεί κανονικά,
**ώστε** να αποφασίσω αν θα φύγω τώρα ή θα επιλέξω άλλη διαδρομή.

- **Given** υπάρχουν πρόσφατες συμφωνούσες αναφορές για 10΄ καθυστέρηση
  **When** ζητώ την κατάσταση της γραμμής
  **Then** βλέπω «Μικρή καθυστέρηση» με εκτίμηση 10 λεπτών.
  → `test_aggregation.py::TestConsensus::test_unanimous_reports_produce_that_value`
- **Given** η μόνη αναφορά έγινε πριν 45 λεπτά
  **When** ζητώ την κατάσταση
  **Then** βλέπω «Άγνωστο», όχι παλιά δεδομένα παρουσιασμένα ως τρέχοντα.
  → `test_aggregation.py::TestTimeWindow::test_expired_reports_are_ignored`

### US-05 · Ειλικρίνεια στην αβεβαιότητα `M`

**Ως** επιβάτης,
**θέλω** το σύστημα να παραδέχεται πότε δεν ξέρει,
**ώστε** να μην πάρω απόφαση βασισμένος σε ψευδή βεβαιότητα.

- **Given** δύο χρήστες αναφέρουν ριζικά διαφορετικές καθυστερήσεις (2΄ και 40΄)
  **When** υπολογίζεται η κατάσταση
  **Then** το σύστημα επιστρέφει «Άγνωστο» με χαμηλό βαθμό εμπιστοσύνης.
  → `test_aggregation.py::TestDisagreement::test_wide_disagreement_suppresses_the_status`
- **Given** υπάρχει μόνο μία αναφορά
  **When** ζητώ την κατάσταση
  **Then** δεν δηλώνεται κατάσταση.
  → `test_aggregation.py::TestInsufficientData::test_single_report_is_not_enough`

### US-06 · Ανθεκτικότητα σε υπερβολές `M`

**Ως** επιβάτης,
**θέλω** μια ακραία ή κακόβουλη αναφορά να μην αλλοιώνει την εικόνα,
**ώστε** να εμπιστεύομαι τον αριθμό που βλέπω.

- **Given** τέσσερις αναφορές γύρω στα 12΄ και μία στα 90΄
  **When** υπολογίζεται η εκτίμηση
  **Then** η ακραία τιμή απορρίπτεται και η εκτίμηση παραμένει στα ~12΄.
  → `test_aggregation.py::TestOutlierRejection::test_wild_outlier_is_discarded`
- **Given** χρήστης με χαμηλό βαθμό αξιοπιστίας αναφέρει 60΄ ενώ τρεις αξιόπιστοι αναφέρουν 3΄
  **When** υπολογίζεται η εκτίμηση
  **Then** η εκτίμηση παραμένει στα 3΄.
  → `test_aggregation.py::TestWeighting::test_unreliable_author_cannot_move_the_estimate`

### US-07 · Προτεραιότητα στα φρέσκα δεδομένα `S`

**Ως** επιβάτης,
**θέλω** η εικόνα να αντανακλά το τώρα και όχι το πριν μισή ώρα,
**ώστε** να μη χάσω μια κατάσταση που μόλις επιδεινώθηκε.

- **Given** δύο πρόσφατες αναφορές για 20΄ και δύο σχεδόν ληγμένες για 2΄
  **When** υπολογίζεται η εκτίμηση
  **Then** υπερισχύουν οι πρόσφατες.
  → `test_aggregation.py::TestWeighting::test_fresh_reports_outweigh_stale_ones`

## Επικός στόχος Γ — Εποπτεία από τον φορέα

### US-08 · Dashboard προβληματικών γραμμών `S`

**Ως** χειριστής του φορέα,
**θέλω** να βλέπω κατάταξη γραμμών κατά ένταση αναφορών,
**ώστε** να εντοπίζω συστημικά προβλήματα και όχι μεμονωμένα περιστατικά.

- **Given** έχω ρόλο χειριστή
  **When** ανοίγω το dashboard
  **Then** βλέπω τις γραμμές ταξινομημένες κατά εκτιμώμενη καθυστέρηση, με
  πλήθος αναφορών και βαθμό εμπιστοσύνης ανά γραμμή.
- **Given** έχω ρόλο απλού επιβάτη
  **When** ζητώ το dashboard
  **Then** λαμβάνω `403`.

### US-09 · Επίσημη διαταραχή `C`

**Ως** χειριστής,
**θέλω** να καταχωρίσω επίσημη διακοπή που υπερισχύει των αναφορών,
**ώστε** η επίσημη πληροφορία να μην έπεται της ανεπίσημης.

### US-10 · Ιχνηλασιμότητα εκτίμησης `C`

**Ως** υπεύθυνος λειτουργίας,
**θέλω** να βλέπω ποιες αναφορές συνέβαλαν σε μια εκτίμηση,
**ώστε** να μπορώ να ελέγξω περιστατικό κατάχρησης εκ των υστέρων.

- **Given** υπολογίστηκε εκτίμηση για γραμμή
  **When** εξετάζω το αποτέλεσμα
  **Then** περιλαμβάνει τα `used_report_ids` και το πλήθος όσων απορρίφθηκαν.
  → `test_aggregation.py::TestConsensus::test_used_report_ids_are_reported_for_auditability`
