## 2026-08-28 · Συνεδρία 2 — Πρώτη εκτέλεση pipeline και αποτυχία στο Build

**Τι ζητήθηκε:** Push του repository στο GitHub και επαλήθευση ότι το pipeline
τρέχει.

**Τι συνέβη:** Το run #1 απέτυχε. Στάδια 1 και 2 πράσινα (lint, και tests σε
Python 3.11 και 3.12), **στάδιο 3 κόκκινο**, στάδιο 4 παραλείφθηκε λόγω
εξάρτησης.

**Αιτία:** Το repository είχε ονομαστεί με ελληνικούς χαρακτήρες, τους οποίους
το GitHub αφαίρεσε, αφήνοντας το όνομα `-delay-reports` — με παύλα στην αρχή.
Το πρότυπο ονοματοδοσίας των Docker images απαιτεί κάθε τμήμα της διαδρομής να
ξεκινά με πεζό γράμμα ή ψηφίο, οπότε το `ghcr.io/<owner>/-delay-reports` ήταν
συντακτικά άκυρο και το push του image απέτυχε.

**Τι διορθώθηκε:**

1. Μετονομασία του repository σε `mmm-delay-reports`.
2. Προσθήκη βήματος **κανονικοποίησης ονόματος image** στο workflow: μετατροπή
   σε πεζά και αφαίρεση μη αλφαριθμητικών χαρακτήρων από την αρχή του ονόματος.
   Η μετονομασία μόνη της θα αρκούσε, αλλά αφήνει το pipeline να εξαρτάται από
   μια σύμβαση που κανείς δεν επιβάλλει. Το βήμα κάνει την απαίτηση ρητή.
3. Αντικατάσταση του smoke test ώστε να τρέχει το image **μέσω του digest** που
   επιστρέφει το βήμα build, αντί για ετικέτα που ανακατασκευαζόταν με
   `git rev-parse --short HEAD`. Η παλιά μορφή θα μπορούσε σιωπηλά να δοκιμάζει
   διαφορετικό image από αυτό που μόλις χτίστηκε.

**Τι κρατήθηκε ως τεκμήριο:** Στιγμιότυπο του αποτυχημένου run #1. **Ένα
pipeline που εντοπίζει πραγματικό πρόβλημα πριν αυτό φτάσει στην παραγωγή
αποδεικνύει την αξία του καλύτερα από δέκα διαδοχικά πράσινα runs.** Το
περιστατικό τεκμηριώνεται στο κεφάλαιο 9 μαζί με τη διόρθωση.

**Δίδαγμα για το κεφάλαιο 6:** Ο agent δεν είχε τρόπο να προβλέψει αυτή την
αποτυχία τοπικά — στο περιβάλλον ανάπτυξης δεν υπήρχε διαθέσιμος docker daemon,
οπότε το `Dockerfile` και το στάδιο build δεν είχαν δοκιμαστεί ποτέ πραγματικά.
Αυτό ήταν γνωστός περιορισμός και είχε δηλωθεί ρητά αντί να αποσιωπηθεί. Το
συμπέρασμα δεν είναι «ο agent έκανε λάθος» αλλά **«ό,τι δεν έχει εκτελεστεί δεν
έχει επαληθευτεί»** — αρχή που ισχύει εξίσου για κώδικα γραμμένο από άνθρωπο.

## 2026-08-28 · Συνεδρία 3 — Μοντέλο δεδομένων και migrations

**Τι ζητήθηκε:** Έναρξη Φάσης 2: μοντέλα ORM, migrations, seed δεδομένα, και
η υπηρεσία που ενώνει τη βάση με τον καθαρό πυρήνα.

**Τι παρήχθη:** `app/models.py`, `app/db.py`, `app/config.py`, `app/seed.py`,
`app/services/line_status.py`, Alembic migration `0001_initial`, και 36 νέα
tests (σύνολο 104, κάλυψη 99%).

**Τι κρατήθηκε:**

- **Ο βαθμός αξιοπιστίας δεν αποθηκεύεται.** Αποθηκεύονται μόνο τα σωρευτικά
  πλήθη ψήφων και ο βαθμός υπολογίζεται τη στιγμή της συνάθροισης. Έτσι μια
  αλλαγή στον τύπο ισχύει αναδρομικά, χωρίς migration και χωρίς κίνδυνο να
  μείνουν ασυνεπείς αποθηκευμένες τιμές.
- **Οι κανόνες ακεραιότητας επιβάλλονται στη βάση**, όχι μόνο στον κώδικα: μία
  ψήφος ανά χρήστη ανά αναφορά, όρια τιμής καθυστέρησης, μοναδικότητα σειράς
  στάσης. Ένας κανόνας που ζει μόνο σε ένα `if` σπάει στο πρώτο ταυτόχρονο
  αίτημα.

**Τι απορρίφθηκε ή διορθώθηκε:**

- **Χρονοσημάνσεις με ζώνη ώρας.** Η πρώτη γραφή χρησιμοποιούσε
  `DateTime(timezone=True)` και `datetime.now(UTC)`. Το SQLite όμως δεν
  διατηρεί πληροφορία ζώνης ώρας ενώ η PostgreSQL τη διατηρεί — τα tests θα
  σύγκριναν naive με aware χρόνους και θα έσπαγαν **μόνο στην παραγωγή**.
  Υιοθετήθηκε σύμβαση naive UTC παντού, με ρητή τεκμηρίωση του γιατί.
- **Τα foreign keys του SQLite** είναι εξ ορισμού ανενεργά. Χωρίς ρητή
  ενεργοποίηση (`PRAGMA foreign_keys=ON`), τα tests θα περνούσαν με δεδομένα
  που η PostgreSQL θα απέρριπτε — δηλαδή θα δοκιμάζαμε άλλο σύστημα από αυτό
  που παραδίδουμε.
- **Το lint στα αρχεία migration** απορρίφθηκε ως απαίτηση: παράγονται από το
  Alembic και η μορφοποίησή τους δεν είναι δική μας απόφαση. Εξαιρέθηκαν ρητά
  αντί να «διορθώνονται» με το χέρι μετά από κάθε autogenerate.

**Πρακτική που αξίζει να αναφερθεί στο κεφάλαιο 6 — επαλήθευση ότι ένα test
μπορεί να αποτύχει:** Γράφτηκε test που ανεβάζει καθαρή βάση **μόνο με
migrations** και τη συγκρίνει με τα μοντέλα, ώστε να πιάνεται η κλασική
απόκλιση «άλλαξα μοντέλο, ξέχασα migration». Πέρασε με την πρώτη — που είναι
ύποπτο. Προστέθηκε προσωρινά μια πλασματική στήλη στο μοντέλο `Report` για να
επιβεβαιωθεί ότι το test **όντως κοκκινίζει**. Κοκκίνισε με το σωστό μήνυμα
(`Detected added column 'reports.drift_probe'`), η στήλη αφαιρέθηκε.
*Ένα test που δεν το έχεις δει να αποτυγχάνει δεν είναι test — είναι
διακόσμηση.*

**Τι δεν έχει επαληθευτεί:** Η αλλαγή στο `Dockerfile` (εκτέλεση
`alembic upgrade head` πριν τον server) δεν δοκιμάστηκε τοπικά — δεν υπήρχε
διαθέσιμος docker daemon στο περιβάλλον ανάπτυξης. Το smoke test του σταδίου 3
είναι ακριβώς ο μηχανισμός που θα το πιάσει αν είναι λάθος.

## 2026-08-28 · Συνεδρία 4 — Ταυτοποίηση και REST API

**Τι ζητήθηκε:** Ολοκλήρωση του backend: εγγραφή/σύνδεση με JWT, ρόλοι, και τα
endpoints γραμμών, αναφορών, ψήφων και dashboard.

**Τι παρήχθη:** `app/security.py`, `app/deps.py`, `app/schemas.py`, τέσσερις
routers, `.env.example`. 45 νέα tests — σύνολο **149, κάλυψη 99%**.

**Τι κρατήθηκε:**

- **Η ανάγνωση δεν απαιτεί σύνδεση, η υποβολή απαιτεί.** Απόφαση που προέκυψε
  απευθείας από τη User Journey Α: ο περιστασιακός επιβάτης που συναντά οθόνη
  εγγραφής κλείνει την εφαρμογή.
- **Λάθος email και λάθος κωδικός δίνουν πανομοιότυπη απόκριση.** Διαφορετικά
  μηνύματα επιτρέπουν απαρίθμηση λογαριασμών. Υπάρχει test που συγκρίνει τις
  δύο αποκρίσεις byte προς byte.
- **Ο ρόλος χειριστή δεν δίνεται από το endpoint εγγραφής.** Θα ήταν κλιμάκωση
  δικαιωμάτων με μία γραμμή JSON· υπάρχει test που το επιβεβαιώνει.
- **Κανείς δεν ψηφίζει τη δική του αναφορά** — αλλιώς ο καθένας ανεβάζει μόνος
  του τον βαθμό αξιοπιστίας του.

**Τι απορρίφθηκε ή διορθώθηκε:**

- **`passlib` → `bcrypt` απευθείας.** Το `passlib` είναι αδρανές εδώ και χρόνια
  και σπάει με τις νεότερες εκδόσεις του `bcrypt`. Ένα επίπεδο αφαίρεσης που
  δεν συντηρείται είναι ρίσκο, όχι διευκόλυνση.
- **Σιωπηλή περικοπή κωδικού.** Το bcrypt αγνοεί ό,τι ξεπερνά τα 72 bytes —
  δύο διαφορετικοί μακροί κωδικοί θα ταίριαζαν μεταξύ τους. Ο κωδικός
  απορρίπτεται ρητά αντί να περικόπτεται.

**Τρία σφάλματα που εντόπισαν τα tests, όχι η ανάγνωση του κώδικα:**

1. **`no such table: users` στα tests του API.** Το FastAPI εκτελεί τα σύγχρονα
   endpoints σε threadpool, και μια βάση SQLite στη μνήμη ζει *μέσα* στη
   σύνδεση. Με το προεπιλεγμένο pool κάθε νήμα άνοιγε δική του, άδεια βάση.
   Λύση: `StaticPool` — μία σύνδεση για όλα τα νήματα.
2. **500 αντί για 409 στη διπλή ψήφο.** Η ανάγνωση της σχέσης `report.author`
   *μετά* το `session.add()` πυροδοτούσε autoflush, οπότε η παραβίαση του
   περιορισμού μοναδικότητας έσκαγε **εκτός** του `try/except`. Λύση:
   ανάγνωση του συντάκτη πριν την προσθήκη.
3. **Σειρά διαδρομών.** Η `/lines/by-code/{code}` έπρεπε να δηλωθεί *πριν* από
   την `/lines/{line_id}`, αλλιώς το FastAPI προσπαθούσε να μετατρέψει το
   «by-code» σε ακέραιο.

Και τα τρία είναι σφάλματα που **δεν φαίνονται διαβάζοντας τον κώδικα** — μόνο
εκτελώντας τον. Ενισχύουν το επιχείρημα του κεφαλαίου 8: τα automated tests δεν
είναι γραφειοκρατία, είναι ο μόνος τρόπος να μάθεις τι κάνει πραγματικά το
σύστημα.

**Το σφάλμα που προλήφθηκε:** Ο πάροχος δίνει URL της μορφής `postgres://…`,

μετατροπή μπήκε στο `app/config.py` και καλύφθηκε από 8 tests. **Ένα σφάλμα
παραγωγής μετατράπηκε σε κάτι που πιάνει ένα unit test.**

**Απόφαση:** Η υποδομή περιγράφεται σε αρχείο αντί να στηθεί με κλικ. Ό,τι
στήνεται με κλικ δεν τεκμηριώνεται, δεν εκδίδεται και δεν ξαναστήνεται.

## 2026-09-03 · Συνεδρία 6 — Πρώτο deployment και ένας περιορισμός που βγήκε σε καλό

**Τι ζητήθηκε:** Deployment στο Render και επαλήθευση της αλυσίδας.

**Τι συνέβη:** Το blueprint εφαρμόστηκε, η υπηρεσία και η PostgreSQL στήθηκαν,
το `/health` απάντησε. Η βάση παραγωγής όμως ήταν άδεια και το σχέδιο ήταν να
τρέξει το seed με το χέρι από το shell της υπηρεσίας.

**Ο περιορισμός:** Η δωρεάν βαθμίδα του Render **δεν παρέχει πρόσβαση σε
shell**. Δεν υπήρχε τρόπος να εκτελεστεί χειροκίνητη εντολή στην παραγωγή.

**Τι κρατήθηκε:** Αντί να αναζητηθεί παράκαμψη (προσωρινό endpoint που θα
έτρεχε το seed — απορρίφθηκε ως κενό ασφαλείας), το βήμα μπήκε στην εντολή
εκκίνησης του container, ανάμεσα στα migrations και στον server:

```
alembic upgrade head && python -m app.seed && uvicorn app.main:app …
```

Ο περιορισμός αποδείχθηκε ωφέλιμος: **ανάγκασε το bootstrap των δεδομένων
αναφοράς να γίνει μέρος της αυτοματοποιημένης διαδικασίας** αντί για
χειροκίνητο βήμα που κάποιος θα ξεχνούσε μετά από κάθε ανακατασκευή.

**Επαλήθευση πριν το push:** Η εντολή εκτελέστηκε δύο φορές σε σειρά σε καθαρή
βάση. Πρώτη φορά «προστέθηκαν 10 γραμμές», δεύτερη «καμία αλλαγή» — απόδειξη
ότι είναι ιδεμπόσταστη και ακίνδυνη σε κάθε επανεκκίνηση.

**Αποτέλεσμα:** Το στάδιο 4 του pipeline κάλεσε το deploy hook και το Render
απάντησε με αναγνωριστικό deployment. Ολόκληρη η αλυσίδα από την ενσωμάτωση
μέχρι τη ζωντανή εφαρμογή διήρκεσε περίπου δύο λεπτά, χωρίς ανθρώπινη
παρέμβαση.

## 2026-09-03 · Συνεδρία 7 — Συγγραφή του παραδοτέου

**Πώς γράφτηκε:** Από τα αρχεία του `docs/` και από αυτό εδώ το ημερολόγιο.

**Δύο διορθώσεις μετά την ενσωμάτωση των στιγμιότυπων:** Το κείμενο ισχυριζόταν
ότι το ruleset απαγορεύει και τη διαγραφή του branch, ενώ το στιγμιότυπο
έδειχνε μόνο `Block force pushes`. Επίσης μια λεζάντα υποσχόταν logs με
migration και seed, ενώ η εικόνα έδειχνε την οθόνη του ολοκληρωμένου
deployment. Και τα δύο διορθώθηκαν ώστε το κείμενο να λέει ό,τι δείχνει η
εικόνα. *Η αντιπαραβολή ισχυρισμού και τεκμηρίου είναι μέρος της συγγραφής,
όχι φορμαλισμός.*

**Ενημέρωση του repository:** Τα `PLAN.md`, `TASKS.md`, `CLAUDE.md` και
`ARCHITECTURE.md` ενημερώθηκαν ώστε να συμφωνούν με το παραδοτέο — ιδίως η
αφαίρεση των αναφορών σε γραφική διεπαφή React, η οποία τελικά δεν
υλοποιήθηκε. Ένα repository που υπόσχεται κάτι που δεν υπάρχει υπονομεύει την
ίδια την τεκμηρίωση που το επικαλείται.
